# 一、项目理念与原则

## 总体思想

1. 本项目的目的是为乾隆大藏经的影印版提供数字化索引。
2. 最开始的想法是"只校不对"。所谓只校，图片是什么，文本就是什么；所谓不对，图片内容对不对非本人力所能及。
3. 所以定下一个"完全一样"的原则。就是一模一样，完全忠实于原本。
4. 实际情况困难重重。主要的问题是，原影印版自身错漏，或相互不一致。
5. 所以改为"完全一致"，就是根据册目录、正文、总目录、勘误表的情况，取一个最好结果。
6. 但是还是继续坚持"一模一样"，如果做不到，就调整为"完全一致"。
7. 所谓"完全一致"，只以影印版自身为依据；所有不得不"完全一致"的地方，全部标出来，留待后来者继续校验。
8. 优先级：册目录、正文（主要是封面和首页）、总目录、校勘表。

## 千字文索引和数字化索引

1. 千字文索引是大藏经中主要的检索办法。知道经名，就可以找到千字文索引；知道千字文，就可以找到实体书。
2. 数字化索引则是要给出某部经（包括卷）从哪一册哪一页开始。
3. 经的序号、卷的序号、册的序号、页码这四种信息全部来自影印版。
4. 本数字化索引也包括了千字文信息，但只起核对作用，没有定位作用。
5. 本数字化索引不设计任何内部 id。

## 卷和册的概念

1. 比如五经同卷，实际上就是五部经共用一个千字文编号。这个时候卷是物理概念。
2. "全藏共 724 函，每函 10 册，共计 7240 册"。这句话中的"册"，对应"五经同卷"的"卷"。
3. 木质经版的集合是册，印刷后就是卷。
4. 但是卷可能同时也是逻辑概念。比如大般若经的第一卷，卷一（天一），"卷一"是逻辑概念，而"天一"是物理概念。
5. "乾隆大藏经由北京佛教协会广化寺监印，中国书店于 2008 年 12 月出版。开本为 16 开，共 168 册，印张 8242。"
6. "168 册"是现代出版发行时编辑的形式，包括其中每一册中的页码，是用现代技术加上去的。
7. 本数字化索引的工作，就是将乾隆大藏经中自带的第几部第几卷，对应到现在出版发行的第几册第几页上去。

## 发现错误不要紧张

1. 圣人也会犯错，何况大藏经是凡夫编撰的，发现问题不用大惊小怪，影印版就包括勘误表。
2. 而且索引是工具，是方便，不牵涉义理。
3. 但还是要有一种科学的方法，实事求是的态度。尊重三宝，尊重法宝。
4. 所谓科学的方法，千字文索引是科学的方法，数字化索引也是。
5. 所谓实事求是的态度，影印版自带的勘误表即是，沿用这个格式，则态度也有了。


# 二、具体问题与处理办法

## 索引和页面不一致的情况

1. 首先是目录，而暂不考虑内容。
2. 为了避免混乱，以第一优先级的册目录为标准，和这个标准不一样的，都需要说明。
3. 比如，原索引没有作者信息的，校勘表中有。
4. 比如，索引和正文不一致的，以索引为准。说明为什么。
5. 比如，索引和正文不一致的，以正文为结果。也要说明为什么。
6. 比如，校勘表指出，"友"和"枝"应对调。为什么对调，按照千字文，对调后顺序才对。问题是图片和索引都按错误的次序施工完毕了。怎么办呢？我的意思是保持这种错误的样子。因为这个千字文，就是一个大藏经门牌号，按照千字文规划施工。实际施工错了，那就只好将错就错，才能找到正确的经文。至于千字文顺序不对了，不是特别要紧的事情。千字文是个工具。
7. 比如，校勘表指出，40 册最后的"能九"应该改为"能八"。为什么呢，因为"能九"的大部分在 41 册，只有这么几页在 40 册。导致了千字文跨册了。这个感觉就不对的。因为一个字一函，这个字都不跨函，何况更大的单位册。所以变成"能八"是合理的。问题是经文上已经印了能九了呀。其实调整这个册也是可以的，把这部经放入下一册不就行了吗？如果不改，可能导致实际上在能九找不到这部经。那就予以说明好了。
8. 校对说明的原则，就是如果和册索引不一致，全部进行说明。
9. 至于要不要修改，也是个问题。一个原则是能不改就不改。
10. 如果要改，就是索引的页码错了，直接违反初衷，还是不好的。如果页码错了，还是要改的。其它能不改就不改。

## 指向共享封面的问题

### 第 879 部经首页指向

索引指向十二经同卷的一个单独封面；
卷一指向实际经文的卷一；
经本身没有单独经文首页，十二部经共享一个"十二经同卷的封面"。

1. 问题是，它的经题指向"十二经同卷"，而卷一指向经文实际第一卷。两者隔了一页。
2. 实际上，二经同卷、三经同卷、四经同卷时，封面上都有经题，而且这个经题属于第一部经。
3. 所以，五经同卷或更多经同卷时，经文题目写不下了，写到后序页中，那么这个封面也属于第一部经比较合适。
4. 多经同卷时，第一部经没有多卷，就是在 index.html 中，直接指向这个共享的封面就好了。
5. 这个中间隔了一页的小索引，不属于经题，也不属于正文的卷一，也许空也是一种选择。

### 第 929 部经有上下两卷，又是二经同卷第一部

1. 按照上下两卷，需要单独列目录，单独指向经文单独的首页。
2. 按照二经同卷，应该指向共享的多经封面。
3. 实际上上面两者指向同一个地方。再看下目录，目录指向共享封面。
4. 实际上还是有个选择。多经同卷的时候，第一部经通常只有一卷，所以没有 idx 文件。
5. 但是这部经因为分成了两卷，实际上有。

### 第 849 部经也是和第 929 部经情况一样

现在也是作为 idx 处理。但是经的 title 点击时，指向"五经一卷"，实际上就是经的封面，和大藏经索引一致的。

### 第 951 部是五经同卷的首部经

应该指向共享封面，没有指向。再去看下索引。索引指向 521，现在指向 522，所以应该修改。

### 第 1071 部经只有一卷但有序，又是四讃二颂的开始一部

1. 有序，所以有一个单独的 idx.html 文件，用来展示子目录。
2. 多经同卷的第一部，所以经题指向封面。
3. 所以，所有这种情况，都可以逻辑一致地予以处理了。

这个应该比较合适了。

### 解决方案参考

方案一：使用完整的 Web 字体（最推荐）
创建字体子集：使用工具（如字蛛或 Transfonter）分析页面，生成只包含生僻字的 .woff2 字体文件。
通过 CSS 加载：使用 @font-face 规则加载，设置为这些生僻字的优先字体。

方案二：图片回退
用 CSS @supports 检测字体渲染结果，如果显示为方块，则用透明元素替换并显示包含该字的小图片。

方案三：使用 CDN 上的开源大字符集字体
引用 Google Fonts 等 CDN 上的 Noto Sans CJK SC 等字体，但文件较大（10-20MB），移动端需谨慎。

## index.html 的校验

这个文件就是本数字化索引的主要成果，需要对其进行校验。
这个是校对工作，但是和前面的工作有质的区别。
这部分工作如果错了，是数字化索引工程发生的错误，直接改正即可。
前面的校对工作，如果和影印版不一致，那是需要说明的。

### 校验规则

1. `<head><title>` 中的经文名和 `<h1>` 中经文名必须一样。
2. `<head><title>` 中的经文名，应该不带卷数。
3. `<h1>` 中的册数（前三位数字）和 `<h2>` 中的册数必须一样。
4. 所有 start 和 end 必须首尾相续，同一个 `<a>` 中，start 和 end 可以相同。
5. 每个 page 页的数字，必须和它所在的 `<tr>` 的 `<a>` 中的 start 的后面三位相同。如果 start 长度是 7，则是后面四位。
6. 每卷的索引，都可以导航本经的最后一页。这样翻页的时候更加自然。
